# ESPN Europa and Conference Provider Implementation Plan

**Goal:** Populate EL and Conference League from ESPN public JSON while retaining football-data.org for CL, existing competition/season contracts and safe shared team identities.

**Architecture:** A bounded cached ESPN client parses external payloads into validated records. A dedicated ingestion service resolves persistent provider IDs to canonical teams/matches and writes one competition-season atomically. Existing DataService dispatches EL/UCL to ESPN; CL ingestion stays on its present provider. Database-only views do not require a football-data credential.

**Tech stack:** Existing Python, httpx, DuckDB, FastAPI, pytest and browser suite. No new package, provider plugin framework, UI redesign or production actions.

**Mode:** tested. New hermetic payload, identity, ingestion, failure and integration regressions; live read-only source check on a temporary database only. No commits, pushes, worktrees, remote production writes, credential inspection or deployment in this implementation step. Preserve pre-existing changes.

## 1. Design decisions and why

- Provider routing is explicit: CL -> football-data.org, EL -> ESPN `uefa.europa`, UCL -> ESPN `uefa.europa.conf`. No 403-triggered fallback to another competition or silent provider mixing.
- ESPN standings: `/apis/v2/sports/soccer/{slug}/standings?season={year}`. Fixtures: `/apis/site/v2/sports/soccer/{slug}/scoreboard?dates={year}&limit=1000` and following calendar year, deduplicated by event ID and filtered by `event.season.year`. Range-form dates return 400; numeric page is ignored. Validate requested season/competition identities and detect truncation. Keep polite >=0.5s spacing, bounded retries/backoff/timeouts and source-namespaced persistent cache keys. Never cache malformed successes as valid season results.
- Parse known `season.slug` values to stage/round (league-phase, knockout-round-playoffs, round-of-16, quarterfinals, semifinals, final); never use season-varying numeric stage IDs alone. Unknown non-qualifier stage must fail visibly rather than count as league. Qualifiers are not league-phase data. Completed status requires valid per-leg numeric scores, not aggregate/shootout values. Unknown scores are not 0-0.
- Historical target remains 2024/25 onward. Completed new-format league totals are 144 fixtures for EL and 108 for Conference; verify coverage against standings played totals and missing/duplicate fixture checks before any write. Current fixtures may contain future/TBD slots: skip unresolved placeholders with diagnostics, never fabricate team IDs or completed scores. Incomplete/invalid feed preserves existing snapshots and matches.
- Provider IDs must not become canonical IDs directly. Persist `(provider, provider_team_id) -> team_id`. Resolve existing teams by exact clean name or explicit reviewed aliases, with conservative punctuation/case normalization only. Do not use existing aggressive suffix removal/fuzzy matching (United/City collisions). Ambiguous canonical matches fail for review. Allocate bounded negative IDs for genuinely new clubs, checking collisions. Keep canonical established names/crests unless missing; new teams may use ESPN metadata.
- Persist `(provider, event_id) -> match_id`, with deterministic bounded negative candidate IDs and collision guards. On first import reuse a unique existing fixture when competition, season, canonical home/away and stage/round identify the same scheduled leg; date changes may update known mapped fixtures. Ambiguous historical reconciliation fails, never deletes/relabels unrelated data. Prefer raising rather than silently duplicating same fixture under a new provider ID. Legacy matches and team IDs retain provenance; no bulk guessing/migration.
- One transaction covers mappings, new teams, matches and current standings after external requests/validation succeed. No swallowed per-row writes. Current standings snapshot replaces only the selected competition after complete validation; archived ingestion never alters current standings. Other competitions and Elo rows untouched until scheduler's existing pooled replay. All schedules use existing August season bounds.
- The application shares one DuckDB connection between scheduler, background history and request handlers. Protect database query/fetch/commit operations with a shared reentrant lock (`threading.RLock`, created before the connection so a failed-schema `close()` stays safe) and hold it across ESPN's transaction via `Database.transaction()`, which brackets BEGIN/COMMIT/ROLLBACK; otherwise another thread's cache commit could commit a partial ESPN import. Keep HTTP work outside the lock, and test that a competing commit waits until rollback/commit completes (`tests/backend/test_espn_concurrency.py`).
- Missing CL credential disables CL network refresh clearly, not EL/UCL. Existing GET views read stored DB and must remain available without constructing authenticated clients. Historical administrative refresh dispatches ESPN for EL/UCL >=2024 and retains existing CL/older archive sources; no new public mutating route.
- No aggregate/shootout schema expansion: store per-leg scores, preserve existing analyzer's aggregate calculation and documented penalty limitation.

## 2. File-level work

1. `backend/espn_client.py` (new): pure payload parsing/client, slug/season validation, standings statistic mapping, fixture status/stage/date/score mapping, deduplication and cache/HTTP limits. Expose one season fetch operation returning standings + matches (client does not mutate team/match tables).
2. `backend/espn_service.py` (new): identity resolution and transactionally persist validated records; `sync_all(competition_id)` for current year and `sync_season(competition_id, year)` for archives. Expose ingestion counts for verification. Keep source-specific logic out of CL paths.
3. `backend/database.py`: idempotent provider-team and provider-match mapping tables with canonical foreign keys; no changes to existing IDs or existing columns unless strictly necessary. Preserve prior migration guarantees.
4. `backend/fixture_ids.py`: small deterministic provider fixture ID helper, explicit provider namespace and int32 collision checks at persistence.
5. `backend/competitions.py`: provider metadata/helper for routing without changing current public fields incompatibly.
6. `backend/data_service.py`: dispatch current EL/UCL and 2024+ historical ingestion to ESPN; lazy ESPN service so old CL mocks have no side effects; optional CL client and truthful unavailable error for CL requests. Existing `sync_all` and historical administrative entry points remain callable.
7. `backend/scheduler.py`: tolerate missing football-data key, retain single DataService dispatcher and per-competition failures, one Elo replay. Do not start duplicate workers or background jobs.
8. `backend/main.py`: remove needless APIClient construction from database-only analyzer routes; historical refresh can instantiate dispatcher without CL key. Preserve endpoint shapes, validation, proxies and security. Existing startup history fill should check supported ESPN 2024+ windows, not merely pre-2024 European history; don't fetch nonexistent Conference years before inception.
9. Tests: new `tests/backend/test_espn_client.py`, `test_espn_service.py` and integration regressions (plus recorded minimal ESPN payload fixtures as needed). Update only directly obsolete credential expectations in existing tests, preserving prior edits. Test HTTP via MockTransport/mocks, no network in unit suite.
10. Documentation after acceptance: `docs/competitions.md`, README and new `docs/espn-provider.md` for data routing, cache/load, identity reconciliation, incomplete-feed behavior and rollout checks. User selected ESPN after undocumented-API caveat; do not claim official support, licensing approval or stability.

## 3. Acceptance and verification

- EL/UCL ingestion succeeds without EXTERNAL_API_KEY; CL uses original provider when configured and fails independently when not.
- 36-team tables use ESPN statistics accurately; league matches count only selected season/competition, 8/6-game formats handled; current Solkoff has expected opponents and PPG.
- Archived ESPN results reproduce stored league standings without mutating current snapshots. Completed 2024/25 datasets, if available, have 144/108 league fixtures and 189/153 full main-competition fixtures; mismatches are investigated, not hidden.
- Same ESPN team maps consistently across competitions/seasons and onto known canonical teams using safe matching. Similar names never merge implicitly. Mapping survives reopen. Existing historical fixture is reused or ambiguity blocks safely; second sync adds no duplicates; rescheduled event updates original row.
- Foreign/mismatched seasons, malformed stats/scores, unknown stages, truncated season lists, collision, HTTP failure, partial data and DB write failure leave existing data unchanged. Canonical CL teams/matches/standings unchanged by ESPN sync except missing display metadata filled only when safe.
- Cached repeated sync avoids excess requests; no secrets/auth/bypass needed. API retry bounded and no unbounded per-event fetch fanout.
- Run new tests plus all competition/season/knockout regression checks, full frontend and deploy suite. Full backend baseline currently 18 failures (live-server requirements, stale fixture mocks); compare names and report all failures/skips.
- Live read-only smoke limited to needed full season requests with caching, using temporary DB only; report source season, 36-team count, stage counts, league coverage, identity reconciliation decisions, repeated-sync idempotence and archived/current isolation. No production replacement until real data validation and provider identity audit pass, with separate backup/rollback runbook.

## 4. Scope limits

No live score polling, HTML scraping, bot evasion, new paid account, changing CL provider, global fuzzy identity repair, destructive historical replacement, aggregate/penalty feature or production deployment. ESPN endpoints are undocumented and public access does not establish unrestricted reuse rights; keep this operational caveat explicit.

## 5. Execution checkpoint and rollout status

Implemented ESPN client, transactional ingestion, persistent provider mappings, explicit routing, credential-independent stored-data views, semantic cache eviction, source validation and shared-connection transaction locking. Independent review accepted fixes; 81 ESPN-focused tests passed, final combined targeted backend/frontend/deploy checks passed 363 tests, full backend reported 296 passed and the same 18 baseline failures. Current 2026/27 live captures validated 36 clubs and 144/108 fixtures; archive 2024/25 captures validated 189/153. Post-hardening offline replay passed with zero network requests, repeat imports idempotent, archived imports preserved live snapshots.

Production-backup-copy audit found a concrete reconciliation blocker: short/affixed/kickoff-polluted canonical names and legacy NULL-stage fixtures would duplicate clubs and results under an unreviewed takeover. Added fail-closed legacy guards and six tests; backup-copy replay refuses all four current/archive imports and preserves 509 teams, 3,245 matches and zero provider mappings. No automatic alias guessing, guard bypass, production write, deployment, commit or push. A separate reviewed identity/fixture reconciliation plan is required before rollout; copied-backup diagnostics live outside the workspace in `/tmp/opencode/ucl_espn_identity_audit/`.
